# concept-learner · 个人概念学习设计

> 使命：不给你"什么是 X"的静态解释，而是给你"如何学会 X"的动态学习方案。
> 本 Skill 服务的是**一个人**的深度学习，不是一次百科问答。

---

## 一、适用场景

本 Skill 在以下情况启用：

- 想系统学习一个新概念（如 "反向传播"、"哈希一致性"、"大语言模型 RAG"、"Big-O 复杂度"…）
- 面对陌生术语，需要**由浅入深、能动手验证**的学习路径
- 学习常半途而废，需要**明确目标、分步可验收、可复盘**的结构化方法
- 希望学习成果**沉淀到自己的知识仓库**，可长期复用和检索
- 需要一份能对照真实代码/工具实操，而不是只看文字的学习任务书

**不适用**：纯查一个定义/快速答疑（那种情况直接给结论即可，不需要走本流程）。

---

## 二、输入要求（用户需要提供什么）

**必填（最少只需一个概念名即可启动）：**
| 输入 | 说明 | 示例 |
|------|------|------|
| ① 概念名称 | 要学习的对象，尽量精确 | `反向传播 (Backpropagation)` |
| ② 学习深度目标 | 学到什么程度：了解 / 理解会用 / 能实现 | `能手写并用 numpy 实现` |

**强烈建议提供（缺失时我会主动询问或按合理默认推进）：**
| 输入 | 说明 |
|------|------|
| ③ 背景与上下文 | 在学什么课程/项目？这概念服务于什么目标？ |
| ④ 现有基础 | 已掌握的相关前置知识，避免我讲太浅或太深 |
| ⑤ 个人偏好 | 喜欢示例驱动 / 公式推导 / 动手实验 / 类比讲解 |
| ⑥ 可用时间 | 一次学完，还是分多次？每次大概多少分钟 |
| ⑦ 涉及的技术栈 | 用什么语言/工具实践（若需要动手） |

> **约定**：如果用户只给了概念名，不要卡住反复追问，先用"理解会用"的默认深度输出，并在开头标注"已按默认假设，如需调整请告知"。

## 三、工作流程（个人学习设计的核心）

按以下步骤产出，**每一步都面向"这个人怎么学得会、记得住、用得出"**：

### Step 1 · 锚定学习目标
- 明确本次学习的**产出物**（学完能做什么），写成 1~3 条可验收的**行为目标**（不是"理解概念"，而是"能独立实现 X"、"能向他人讲清 Y"）。
- 界定学习边界：本轮**学什么**、**暂不学什么**（防止范围蔓延）。

### Step 2 · 建立心智锚点（Pre-conception）
- 先探测并校准学习者的**前置误解**或**模糊直觉**（常见"错误先验"）。
- 给一个**生活化类比**建立第一直觉，再把类比逐步升级为精确表述。

### Step 3 · 概念分层拆解
- 把概念拆成可独立消化的**子模块/子概念**，标明依赖顺序（哪个是哪个的前置）。
- 每个子概念都标注：**是什么 → 为什么需要 → 解决什么问题**。

### Step 4 · 多角度讲解（因人而异）
- 结合用户偏好提供多种视角：直觉类比、图形示意、公式推导、代码示例、真实场景应用。
- 用**间隔重复**思路：同一核心点用不同表述反复强化。
- 输出**精炼讲解**（不含与学习目标无关的百科式堆砌）。

### Step 5 · 动手实践设计（Learning by Doing）
- 设计 **2~5 个递进的动手任务**：从"最小验证"到"完整应用"。
- 给出明确的**可运行起点**（代码骨架 / 数据集 / 命令）与**验收标准**（跑通的条件、期望输出）。
- 任务要能暴露理解漏洞，而不只是照抄。

### Step 6 · 自测与查漏（Feynman 检验）
- 出 3~6 道分层自测题：概念判断 → 应用题 → 解释给外行听。
- 对每道题给出**自评标准**，让学习者自己判断是真懂还是假懂。
- 标注高频误区与易混淆点，帮助自我纠偏。

### Step 7 · 复盘与归档
- 引导学习者用 3 句话总结"今天学会了什么、卡在哪、下次改进什么"。
- 把学习成果**按第四节路径规范写入仓库**，形成可持续检索的个人知识库。

## 四、输出格式与保存路径

### 输出结构（Markdown，按序组织）
```
# 概念学习：<概念名>

## 🎯 学习目标（行为化、可验收）
## 🧠 前置校准（常见误解 / 生活类比）
## 🧩 概念拆解（子模块 + 依赖图/顺序）
## 📖 核心讲解（多角度）
## 🛠️ 动手实践（递进任务 + 验收标准）
## ✅ 自测题（分层 + 自评标准）
## 📝 个人复盘（3 句话总结）
## 📎 延伸与参考资料
```

### 默认保存路径
- **主仓库根目录**：`learning-materials/`
- 文件命名：`learning_materials/<概念名英文短名或拼音>_<YYYYMMDD>.md`
  - 例：`learning_materials/backpropagation_20260906.md`
- 若仓库同时有 `notes/` 或类似目录且更合适，可放该目录并保持命名一致。

> 保存后，若所在目录是 Git 仓库，建议执行 `git add` 提交归档（仅在用户同意下操作）。

## 五、自检要求（交付前逐条检查）

产出内容在交付前必须通过以下检查，任何一条不满足都要返工：

1. **目标可验收**：学习目标是否为"能做什么"的行为化表述，而非"了解/知道"这类不可检验的描述？
2. **个人化**：是否结合了用户提供的背景、基础与偏好，而非一份可套用任何人的通用百科解释？是否体现了"个人学习设计"？
3. **动手可执行**：是否包含具体的动手任务与明确的**验收标准**（能判断做没做对）？
4. **自测有标准**：是否提供分层自测题，且每题配有让学习者自我判定的**自评标准**？
5. **路径与格式**：是否按第四节规定的 Markdown 结构组织，并给出正确的保存路径与文件名？
6. **安全与范围**：讲解是否仅服务于既定学习目标（无无关堆砌）？是否明确标注了本轮"暂不学"的边界？

> 前 4 条为核心（目标 / 个人化 / 动手 / 自测），缺一不可。

---

## 六、给使用者的说明

- 你可以随时告诉我调整深度、换讲解方式、增加或减少动手任务。
- 学完后把"个人复盘"写下来回传，我会基于你的复盘点，帮你设计下一次进阶学习（形成学习闭环）。
- 建议用本 Skill 覆盖课程中的每一个核心概念，长期积累成**你自己的概念学习库**。
