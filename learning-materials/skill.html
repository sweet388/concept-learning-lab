🎯1. 学习目标（学完能做什么）

学完本资料，你应当能够：
  1. 用一句话说清 AI Agent 里的 Skill 是什么——并明确它不是日常生活的"技能"，而是打包成文件的"程序性知识"。
  2. 讲出一个 Skill 文件的标准结构（SKILL.md + YAML 元数据 + 可选 scripts/references/assets）。
  3. 解释"渐进式披露（progressive disclosure）"——为什么 Agent 不把所有技能塞进上下文。
  4. 说清 Skill 与 MCP/工具/系统提示 的区别（"菜谱" vs "厨具"）。
  5. 指着你自己的 concept-learner/SKILL.md，说明它每一部分对应 Skill 概念的哪一环。
📌 学习边界（本轮暂不深究）：Skill 附带的 Python/Bash 脚本编写、跨平台 Agent Skills 开放标准的完整实现细节、某平台管理后台的配置界面。留到进阶。

❓2. 核心问题（用问题驱动学习）

先带着这 4 个问题去读，读的过程自己找答案：

  1. 我们一直在讲"上下文、提示词"，那 Agent 到底凭什么能稳定地、按统一流程做一件复杂的事，而不是每次随性发挥？
  2. 你刚创建的那个 concept-learner 的 SKILL.md，它是"给模型的知识"还是"让模型干活的方法"？两者差在哪？
  3. 同样是为了让 Agent 用外部能力，Skill 和 MCP（一种连接外部服务的协议）到底分工是什么？
  4. 一个装了 100 个技能的 Agent，为什么不会因为"记得太多"而变慢变笨？它是怎么做到"按需取用"的？

🧠3. 个人化解释（先建直觉，再给定义）

3.1 一个类比：MCP 是"厨具"，Skill 是"菜谱"

AI Agent 行业常把 Skill 和 MCP 的关系比作"菜谱与厨具"：

🔌 MCP / 工具 = "厨具"（能力）

MCP（Model Context Protocol）负责让 Agent 连上外部服务、拿到数据、调用具体操作——像厨房里的刀、烤箱、食材库。它回答的是 "我能碰到/操作什么"。

📖 Skill = "菜谱"（方法）

Skill 教 Agent "这道菜具体怎么做、按什么步骤、用什么标准"——像一份详细菜谱。它回答的是 "活该怎么干、干成什么样"。

✅ 一句话记住：光有厨具（MCP）你不知道做啥菜；光有菜谱（Skill）你没手没脚也做不了。Skill 负责教会方法，MCP/工具负责提供手脚。

3.2 权威定义（大白话翻译）

Anthropic（Claude 的开发者）官方把 Agent Skill 定义为：一个文件夹，里面装着"指令、脚本和资源"，让 Agent 在特定任务上做得更好——本质是把你的工作方法、标准、流程，封装成可重复使用的模块。Skill 一旦创建，Agent 遇到相关任务会自动识别并套用，保证输出的一致性和稳定性。

更技术一点说：Skill 给 Agent 提供的是"程序性知识（procedural knowledge）"——即"怎么做某件事"的步骤与标准，而不是静态的背景知识。它不用重新训练模型、不用改写系统提示，就是一堆可版本化、可审查、可分享的文件。

💡 一个判断标准（很多人引用）：任何你写超过 2 遍的提示词 / 工作流程，都值得考虑封装成一个 Skill。

⚙️4. 核心机制：Skill 怎么工作

4.1 Skill 的标准结构：一个"文件夹"

某个技能目录（如 concept-learner/）
├── SKILL.md      ✅ 必需：Markdown，顶部带 YAML 元数据(name+description)+正文指令
├── scripts/      可选：可执行的 Python / Bash 等代码
├── references/   可选：按需加载的说明文档
└── assets/       可选：模板、字体、图标等

4.2 渐进式披露：为什么装 100 个技能也不"拖慢"模型

这是 Skill 最精妙的设计。它把信息分成 三级，只在需要时才加载，防止把无关技能灌进上下文（呼应你上一课学的 context window 宝贵性）：

层级何时加载装的是什么
第 1 级：YAML 元数据每次任务都常驻只有技能的 name 和 description（极省 token），让 Agent 知道"这技能何时该用"
第 2 级：SKILL.md 正文Agent 判断"这次任务相关"时才加载完整指令、步骤、标准
第 3 级：链接的文件用到了才去翻references/scripts/assets 里的附加材料，按需发现
核心逻辑：Agent 做任务时，扫描所有已装技能的"名称+一句话描述" → 挑出相关的 → 只把那个技能的正文/文件加载进上下文 → 按里面的步骤执行。无关技能全程不占用上下文。
✅ 好处：可组合（多个技能协同）、可移植（一个格式到处用）、高效（只加载当下需要的）、强大（可带真实代码）。你想让 Agent 稳定地按固定流程做事，靠的正是这套机制，而不是每次手写长提示词。

4.3 Skill 与上下文工程的呼应

你在"大模型的上下文"一课里学到：上下文是有限的"桌面"，决定输出质量的是"你精挑后放了什么"。Skill 正是把"放什么"这件事工程化、模块化的产物——它让你把一套高质量的方法论写一次，Agent 需要时精准地、渐进地摆上桌面。

🧪5. 对照实践：你的 concept-learner 技能

这一节把抽象概念落到你刚亲手创建的东西上。你在仓库里建了这样一个技能文件：

.workbuddy/skills/concept-learner/SKILL.md
你 SKILL.md 里的部分对应 Skill 概念的哪一环
顶部 YAML：name: concept-learner + description: 自动生成任意概念的学习资料第 1 级元数据 —— 让 Agent 看到"这是什么技能、何时该用它"。description 写得准，Agent 才会在合适时机触发它。
「适用场景」「输入要求」定义触发条件和前置输入，帮 Agent 判断"这次该不该用、用户要给我什么"。
「7 步工作流程」（锚定目标→…→复盘归档）程序性知识的核心 —— 教会 Agent "做一份学习资料，要按哪几步走"，而不是每次瞎编结构。这就是 Skill vs 普通提示词的差别：流程固定、输出稳定。
「输出格式与保存路径」（learning-materials/…）验收标准 + 可执行动作 —— 告诉 Agent 产物长什么样、放哪，保证一致性。
「6 条自检项」质量控制 —— 让 Agent 交付前自我检查，减少"看起来像回事但不可靠"的输出。
🔬 实践洞察：你已经不知不觉地用上了完整 Skill 机制——因为你的 concept-learner 符合 SKILL.md + YAML 元数据 + 工作流 + 自检 的标准结构。现在调用它学 Agent / 学上下文 / 学 Skill，正是"Agent 扫描到 description 匹配 → 加载该技能 → 按其工作流执行"的活教材。

🧩6. 容易混淆的边界

🔴 Skill ≠ 日常生活的"技能"

本作业讨论的是 AI Agent 系统中的 Skill：一个让 Agent 学会特定做事方法的文件包（程序性知识）。不是"会写代码、会画画"那种人的能力——那些更接近模型靠训练获得的知识/能力。

🔴 Skill ≠ 工具 / MCP

工具/MCP 给 Agent "能力"（能查 API、能操作文件）；Skill 给 Agent "方法"（该怎么用这些能力、按什么步骤）。可以同时用：MCP 提供手脚，Skill 教怎么用手脚。类比：厨具 vs 菜谱。

🔴 Skill ≠ 系统提示 / 项目背景知识

系统提示、项目的"背景资料"是常驻的静态知识（每次都占上下文）；Skill 是按需激活的程序性知识（只在任务相关时才加载），因此更适合"多而不重"。

🔴 Skill ≠ 微调（Fine-tuning）

微调要改模型参数、要训练；Skill 只是普通文件，不改模型、不重训，谁都能用 Markdown 写。这也是它能快速迭代、可审查分享的原因。

💡 一句话辨析：Skill 站在"知识/能力（模型天生的）"和"动作/调用（工具与 MCP 提供的）"之间——它补上的那块，是"知道该怎么一步步做成"的方法与流程。

这个概念我最有切身体会，因为我自己就动手建了 concept-learner。最大的收获是搞清楚：Skill 不是给模型"更多知识"，而是给模型"一套做事的规矩"。我以前总想让 AI "聪明点、记得多点"，现在明白真正让它稳定靠谱的，是把我反复要它做的流程（锚定目标→拆解→自测→归档）写成一份 SKILL.md，它会按需加载照着走——这样每次输出都一个样，不用我每次从头交代。它也让我想通了一件事：想长期用好 AI，与其每次现场写长提示词，不如把"常做的活"沉淀成可复用的技能文件，这才是把经验留下来。

✍️8. 自测问题（做完才算懂）

前 3 题点击判分，后 2 题是口头 Feynman 检验，点开看标准。

1️⃣ 在 AI Agent 领域，"Skill（技能）"最准确的定义是？
2️⃣ "渐进式披露"（progressive disclosure）指的是 Skill 的哪种特性？
3️⃣ 你要让一个 Agent 用公司的 Excel 规范表格做报表。MCP 连接了 Excel。那么"Skill"在其中最可能扮演的角色是？
4️⃣（口头 · Feynman 检验）向一个不懂的人解释：你已经写了一个 concept-learner 的 SKILL.md，为什么现在你让我（AI）去"学 Agent 这个概念"时，我能自动按一套固定流程来，而不是每次随手写？
👉 点开看判断标准
✅ 能说到这个程度 = 真懂了："因为 SKILL.md 顶部的 description 让我判断这个任务该用 concept-learner；我读到匹配后，就把它正文里的 7 步工作流加载进上下文，于是每次都按'锚定目标→心智锚点→…→复盘'走，输出结构就稳定一致了。这就是 Skill 用'方法/流程'控制行为。"

若只答"因为它记住了"而没提到description 触发 + 按需加载 + 固定工作流，请回看 4.2 和第 5 节。
5️⃣（口头 · Feynman 检验）朋友问你："Skill 和 MCP 不都是给 Agent 加能力吗，为啥分开？"你会怎么用"菜谱 vs 厨具"讲清它们的区别，并各自举一个例子？
👉 点开看判断标准
✅ 能说到这个程度 = 真懂了：① MCP = 连接与能力（能否连上/操作外部对象），如"连上公司 Excel 的读写接口"；Skill = 方法与流程（该怎么把活做规范），如"按公司报表规范一步步出表的流程"。② 类比：MCP 是刀和烤箱（厨具），Skill 是"做法式焗蜗牛"的菜谱。③ 二者常配合：Skill 会告诉 Agent 按什么顺序去调用 MCP 工具。

如果分不清"连得上"和"做得对"是两码事，回看 3.1。
